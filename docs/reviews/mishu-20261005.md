## Failures corrected during acceptance

Harness previously discarded optional Chat tools and blocked their execution. A
public registration interface now preserves only registered, active optional tools;
the plugin remains responsible for explicit enablement.

The busy-target admission lock initially overlapped an existing native question.
It is now released before enqueue, and source/target authority is checked again at
actual delivery. The queued-revocation regression verifies the user can answer the
old question and the disabled secretary's queued message never runs.

Browser selection initially raced native startup and reconnect. The menu now waits
for the current Chat to finish opening; selection disables sending while preserving
the draft, and source lifecycle protection prevents a prompt starting during the
background-work check and idle-process replacement.

served-asset probe remains pending. Service restart requires the owner's operational
consent, after which release must wait for running, queued and waiting-answer tasks
