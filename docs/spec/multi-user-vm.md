## 1. 目标与适用范围

服务器 A 手动运行多台 VM，第一版只服务 owner 和一位同事，两人均在同一局域网。每人固定一台专属 VM，通过一个 Web Shell 使用该 VM 内未修改的原版 Pi，获得接近本地 Agent 的代码、命令、测试、Git、文档、文件处理和研究体验。

首版必须交付：个人身份与固定 VM 路由、Pi 原生模型认证与可选 Relay 共存、按对话隔离的 Git worktree、并行工作与受控本地合并、项目文件树、可见且可下载的生成产物、会话归档及故障连续性。

验收规模为 **2 用户 × 每人 3 个活跃对话**；这是测试负载，不是硬性产品上限。不得由此宣称无限并发或生产容量已验证。

### 1.1 Web 界面骨架（2026-09-19 owner 确认的核心体验合同）

owner 要求按大方向收拢，不再逐条追问边缘细节。首版界面就是四块，整体体验对齐 `https://arena.ai/agent/`：

```text
┌──────────┬───────────────────────────┬──────────────┐
│ 左：聊天列表│ 中：当前对话              │ 右：文件树    │
│           │                           │  + 预览/下载  │
│ 项目/归档  │  助手输出、工具摘要、产物   │  + 上传记录   │
├──────────┴───────────────────────────┴──────────────┤
│ 底部：输入框 ＋ Gitea 分支选择 ＋ 发送／停止           │
└─────────────────────────────────────────────────────┘
```

- **左栏**：对话列表（活跃／归档）、新建对话、搜索。
- **中栏**：唯一对话视图，含运行状态、产物卡片和上下文用量。
- **右栏**：当前对话 workspace 的文件树、预览与下载、上传记录；文件仍在用户 VM。
- **底部**：输入框与 Gitea 分支选择同排，另有模型来源／模型选择、附件、停止与发送。

实现状态（2026-09-19，`public/` 与 Host 已改，见 `docs/development/p0-p4-implementation-20260916.md` §1.1 段）：

1. **默认三栏**：`#workspace-panel` 不再带 `hidden`；项目模式下（Host 配置了 `PI_COFFEE_PROJECT_ROOT`）宽屏（>1100px）默认 `.app.files-open` 三列常驻，右栏随当前对话切换；用户点「收起文件」的偏好记在 `localStorage['pi-coffee.files.v1']`。≤1100px 降级为浮层，≤820px 单列。旧单目录模式（无项目根）不显示右栏与分支控件，行为不变。
2. **底部分支选择**：`#start-branch` 文本框已删除，改为输入条左侧的 `#branch` 下拉，数据来自 Host 新动作 `POST /api/workspace {action:"branches"}`（VM 克隆里的本地分支＋远端跟踪分支＋其他对话分支，标出默认分支；不主动 fetch，远端刷新仍按 §5.2 由 Agent 工具完成）。新对话在**首次发消息／上传／改模型来源时才创建 worktree**（惰性创建，起始分支取自下拉）；已打开的对话里下拉显示其 worktree 分支，改选其他分支需确认并**新建一个对话**，不迁移、不切换现有 worktree，也不触碰 §5 合并锁。对话元数据新增 `startBranch`／`startCommit`。
3. 其余三块（左列表、中对话、底输入条）沿用既有实现。

验证方式：`npm run check`（Host 单测覆盖 `branches`／起始分支／远端跟踪分支／非法分支）；`npm run preview:workspace` 用假 Pi 起整套栈看布局；`npm run smoke:workspace-browser` 为 Playwright 版端到端（需本机 Chromium，本轮未跑）。

界面之外的既有合同不变：原生 Pi 执行与历史、统一网关转发、缓存／草稿策略、归档与删除保护。本节只约束布局与可达性，不改变数据归属；具体像素、宽度、动效属实现细节。

## 2. 拓扑、身份和所有权

```text
服务器 A（管理员手动管理 VM、网络、资源和快照）
├─ 统一 Web 入口／轻量网关（唯一公网应用入口，HTTPS）
│   ├─ 静态网页、Gitea 登录、固定用户路由、聊天与文件流式转发
│   ├─ Gitea 用户甲 → 私网 VM-甲的 Host／文件服务
│   └─ Gitea 用户乙 → 私网 VM-乙的 Host／文件服务
├─ VM-甲：Host → 原版 Pi → 供应商原生认证调用
├─ VM-乙：Host → 原版 Pi → 供应商原生认证调用
└─ 可选 Relay：由管理员配置集中模型服务 / 搜索服务

浏览器 ← WebSocket → Web ← 私有传输 → 固定 VM Host ← RPC → Pi
浏览器 ← 同一 HTTPS 入口的文件／预览／下载流 → 网关 ← 私网 → 自己的 VM 文件服务
Pi → 原生供应商（默认）或明确选择的 Relay provider
```

这里的 Web/Relay 可以部署于 A 的适当服务环境，不要求新增自动化虚拟化管理层。

### 2.0 统一入口职责（2026-09-19 确认）

- 复用现有 WebServer、HostClient、HostServer 和 TransferServer，中央 Web 定位为轻量入口／网关，不另建第二套 Agent 平台。
- 默认链路为“浏览器 → 统一 Web → 用户 VM Host → 原生 Pi”，不增加必需的“VM 内 Web”一跳。
- Web 负责页面、Gitea 登录、固定路由、授权与转发；Host/Pi 负责执行、原生历史、Git/worktree 和插件。Pi 原生公共接口、Git 原生命令及已接入插件优先；只补必要薄适配，不修改 Pi 核心或复制原生存储／执行器。
- 最终用户日常体验向 Arena Agent 靠拢，不是要求用户自行使用 VM 终端的技术控制台；复杂开发任务继续在网页内交给同一个 Pi。
- 第三个用户接入只需管理员准备 VM、运行安装脚本、配置该用户原生认证并增加固定路由；不为每用户配置公网端口／证书，不自动分配 VM。
- 首版部署脚本可重复执行、提供检查与报告，不覆盖凭据／历史／项目；身份手工登记，不交付一次性 Enrollment 服务。运维使用诊断命令／报告，不新增网页管理后台。
- Relay 与 Web 的拓扑独立：可选集中模型／搜索 Relay 保留，集中上游密钥不下放 VM；原生模型调用不依赖 Relay。
- 网关与 Host 是独立生命周期：网关关闭、升级或重启不得停止已在 VM 接受的任务；不得用统一关闭 Host/Pi 的 `all` 模式替代该部署保证。


### 2.1 四种身份不能混用

| 身份 | 管理者 | 归属与用途 |
|---|---|---|
| 网页用户 | Gitea + 平台管理员 | Gitea OAuth 标识用户；平台授权用户进入固定 VM |
| VM Host 身份 | 管理员 | 每台 VM 独立连接凭据，仅用于 Web → Host |
| 用户模型认证 | VM 用户，原版 Pi | 凭据留在该 VM 的 Pi 原生存储；不传给 Web |
| Relay 上游与客户端凭据 | 管理员 | 集中上游凭据只在 Relay，VM 仅持有相应客户端凭据 |

一用户固定一 VM；不共享、不自动分配空闲 VM、不允许浏览器指定任意 Host URL。用户缺少路由、VM 离线或凭据失效时 fail-closed，禁止回退到公共或其他用户的 Host。

WebSocket 建连前必须认证、授权并校验允许的 Origin。退出、用户停用、路由撤销与 Cookie 过期必须有明确连接失效行为，不能只隐藏界面。切断网页授权不等同于自动停止该 VM 的后台 Pi 工作；管理员应能在基础设施层面单独处置。

### 2.2 数据边界

- Host 拥有会话生命周期；Web 是交互和转发层，不是 Agent 执行层。
- 持久化对话、Pi 上下文、项目、上传、生成文件和插件状态留在用户 VM。
- 聊天和文件字节可以经过 Web 流式转发，但 Web/Control Plane 不归档正文或文件，不将正文、凭据、授权 URL 放入日志；不建设中央文件库或聊天数据库。文件持久化只在 VM，浏览器只保留下述有限缓存。
- 普通网页登录只能看到自己的 VM、历史、文件和运行状态。
- 管理功能限身份路由与健康等元数据，不提供查看其他用户对话或模型凭据的功能。
- 虚拟化/服务器管理员可能访问磁盘及快照；不承诺防基础设施管理员读取。
- VM 是隔离边界。VM 中拥有命令和文件权限的 Agent 可能访问该 VM 凭据；worktree 和合并锁不是安全沙箱。

### 2.3 网络与部署

统一入口允许对外提供访问；浏览器到入口必须 HTTPS/WSS，采用相应安全 Cookie。旧内网 HTTP 仅可作为明确选择的本地／受信 LAN 部署模式，不能用于公网发布。Gitea OAuth 地址及回调可达性由管理员配置，公开 PI Coffee 不等于必须公开整个内部 Gitea 服务。

浏览器只需访问统一入口，不要求能路由到 VM。Host 与文件服务只在私网监听，并通过防火墙／访问控制只允许必要网关和管理来源访问；用户 VM 不应能访问其他 VM 的 Host 或管理端口。默认每用户 VM 不配置公网映射。

文件上传、预览、下载通过入口的已认证路由流式转发，详见 §7.3。入口是共同的访问故障点及带宽通道；不可达时浏览器可能暂时无法操作，但 Host/Pi 已接受任务继续运行。首版不新增网关集群或高可用控制面。

管理员手动创建、启动、停止 VM，配置资源、网络和快照。部署文档应给出独立身份、服务用户、目录权限、升级与恢复步骤；基础镜像不得包含已登录凭据、真实 Host Token 或用户历史。克隆后须重新登记身份；恢复快照须检查凭据和路由有效性。

## 3. 模型认证：原生默认，Relay 可选

### 3.1 用户路径

1. 用户进入自己的 VM，以 Host 实际运行的 Linux 用户启动原版 Pi。
2. 使用与 Host 一致的 Pi agent 配置目录，完成 Pi 当前版本支持的原生登录或配置。
3. 返回网页，选择该 VM 可用的 provider/model 并运行任务。
4. 需要重新登录时仍可进入 VM；首版不实现网页 OAuth 登录或接管供应商 token 刷新。

继续使用当前锁定的 Pi 版本（核查基线为 `@earendil-works/pi-coding-agent@0.84.4`）。支持范围随该版本原生能力：不新增供应商认证、不重新实现 `/login`、不承诺上游不支持的订阅可用。

“支持所有原生登录方式”指架构不人为删减该能力，不代表所有供应商已实测。验收证据必须区分实际验证的 provider、凭据类型与未验证项。不得收集用户密钥填入 spec 或测试 fixture。

### 3.2 双来源共存

- 原生为默认；用户管理自己的 VM 原生认证。
- Relay 为可选 provider，集中来源由管理员配置，不做用户自行编辑集中密钥的界面。
- 同一 VM 可以同时列出原生和 Relay 模型；界面标注来源，避免误用费用或帐号。
- 原生调用不依赖模型 Relay 在线；搜索使用的 Relay 可独立保留。
- 不因认证、限流、超时自动切换到另一个帐号或 Relay。
- 原有 Relay 环境凭据隔离不能为实现原生登录而整体移除；集中密钥仍不能传入 Pi 子进程。
- 子 Agent 必须解析预期的 provider/model，并复用正确的 VM 原生认证或 Relay 客户端配置。
- 配置变更、认证刷新对已运行 Pi 进程的生效规则必须记录并验证；不得默认所有会话立即热更新。

目标是复用受供应商支持的原版调用方式，不以规避反代检测为验收标准。VM 直连不保证免于风控，共用服务器仍可能共享出口 IP。

## 4. 项目、对话与工作区

### 4.1 领域模型

| 概念 | 定义 |
|---|---|
| User | Gitea 用户，对应一台固定 VM |
| Project | 固定工作根目录下的 Git 项目，持有默认分支，可包含多个对话 |
| Conversation / Pi Session | 网页对话及其 Pi 原生会话；新增对话拥有独立工作区 |
| Conversation workspace | 对话专属目录、Git worktree 和独立分支 |
| Artifact | 上传或 Agent 生成的文件，持久化在 VM，界面引用不代替文件本体 |
| Merge operation | 用户明确触发、项目级互斥的本地集成操作 |

本版以对话为工作单元，不另建未定义的 Task/worker 调度层。同一 Pi 会话依原有排队/插话语义处理命令；不同对话允许并行。

所有项目，包括文档和研究项目，都初始化为 Git 仓库。敏感凭据、Pi 历史和运行状态不得因此进入版本控制。

### 4.2 项目入口（四项均属首版）

- 发现用户在 VM 固定根目录下手动 clone 的项目。
- 网页提交 Git URL，由 VM 使用其 Git 凭据 clone。
- 网页创建空项目并初始化 Git。
- 上传项目压缩包，由 VM 导入为项目。

导入必须处理路径穿越、绝对路径、链接逃逸、覆盖、压缩炸弹和失败清理；解压必须限制文件数、展开体积和允许格式。含现成 `.git` 的压缩包不得未经验证直接作为可执行项目配置启用。具体支持格式和数值上限在实现切片中定稿，失败要有可读错误。

远端 URL 及 Git 操作在 VM 执行；凭据不通过 URL、日志或网页持久化。空仓库必须建立可创建 worktree 的初始提交流程，作者信息缺失时提示配置，不伪造用户身份。

### 4.3 创建对话

用户选择已有项目或新建项目，并可选择起始分支；默认为项目默认分支的当前已提交版本。

- 创建独立目录、独立分支和 worktree，记录准确起始 commit。
- 不复用其他对话的可写工作区，不自动复制其他对话未提交修改。
- 即使多个对话选择同一个起始分支，也必须创建不同的新分支，不能直接让多个 worktree 写同一分支。
- Pi cwd 必须指向该对话 worktree，不能继续将所有会话启动在一个全局 cwd。
- 上传附件按对话隔离，同名文件不能跨对话覆盖。
- 旧会话没有 worktree 时不得伪称已有隔离；迁移方案须先保证可读和可恢复，未经确认不移动或删除旧项目。

固定根目录下的具体磁盘布局、项目索引格式、分支命名方案属于工程细节，但映射应稳定、可恢复且存于 VM。

## 5. 并发、Git 与本地合并

### 5.1 并发边界

同一用户可同时运行多个对话，各自在独立 worktree 工作。同一帐号的多个浏览器窗口允许查看和操作，服务端是状态与排队的权威，不能依赖前端禁用按钮保证互斥。重复操作应能关联请求并避免重复创建或合并。

### 5.2 提交与远端操作

Agent 可在自己的分支修改、测试、提交；回答结束不自动触发平台提交或合并。用户通过已有 Agent 工具执行 push、创建 PR 等远端工作，所需 Git/CLI 凭据留在 VM。产品不另外实现远端 PR 管理器，不随本地合并自动 push。

### 5.3 平台合并流程

1. 用户查看变更摘要和 diff，明确确认合入项目默认分支。
2. 按项目获取互斥锁；不同项目互不阻塞。
3. 检查源和目标状态：不得静默丢弃未提交修改；目标工作区不干净时拒绝。
4. 校验用户查看的分支 heads/diff 仍有效；发生变化时重新展示并确认。
5. 执行本地合并，记录结果；异常和重启后可识别未完成操作，不留下永久假锁。
6. 冲突时停止并显示冲突，不强推、不自动选一方、不静默覆盖。用户让 Agent 在对话分支解决后再次发起合并。

合并期间其他对话仍可在自己的 worktree 工作；正在被合并的源工作区必须避免修改竞争，例如等待其运行结束并阻止平台同时写入。具体互斥实现需测试源 head 变化和双窗口重复请求。

首版不提供网页三方冲突编辑器。默认采用何种 merge 策略、目标集成工作区如何布置，在实现切片明确，不凭空加入 squash/rebase 产品要求。

**锁的承诺只覆盖平台合并流程。** 可信用户或 Agent 可直接运行 Git 绕过该流程；通过提示和工作约定约束，不新增命令权限系统，不宣称能强制禁止绕过。

## 6. 历史、归档与删除

- 主界面默认只能归档，不提供直接彻底删除。
- 归档不删除对话历史、worktree、分支、上传和生成文件。
- 彻底删除入口只在归档界面，必须再次确认。
- 确认前明确列出将删除和将保留的内容：Pi 历史、workspace 目录、分支、附件和产物分别说明，不能只写“删除会话”。
- 不默认让“删除聊天记录”连带删除代码；工作区、分支和文件清理需要单独明确选择/确认。
- 未提交或未合并内容必须醒目标识，未经明确授权不执行破坏性清理；运行中或合并中的工作区应阻止删除。
- 删除流程与多窗口状态同步，失败不得报告完全成功；不能删除其他对话共享的项目仓库。

归档状态及生命周期元数据留在 VM。具体归档按钮对运行任务的交互提示待实现定稿，但归档动作本身不应隐式取消任务。

## 7. 文件树、上传和产物展示

### 界面补充（owner 2026-09-16）

布局与交互参考当前 Arena.ai 工作台：左侧项目/对话导航、中央聊天与输入、右侧文件/产物面板；沿现有前端渐进实现，小屏支持折叠。不复制品牌，不把参考布局当作新增桌面或服务预览功能。


### 7.1 文件树

提供当前对话 worktree/工作目录的项目文件列表，可浏览子目录、刷新和下载。另提供本对话上传文件列表。首版不做整个 VM 文件管理器，不在文件树提供编辑、移动、删除操作。

文件 API 对每个操作检查所属 VM/会话及允许目录，使用实际路径校验防目录穿越和符号链接逃逸；`.git`、平台运行状态和敏感配置不因文件树而自动公开。

已有 LocalSend 上传下载及 VM 端路径／发布保护继续复用，通过统一网关转发，不重新设计一套上传协议；浏览器不再必须直接调用 VM 地址。不能继续将无身份的 `shared` 兼容模式默认暴露给产品用户。文件授权应与用户的 VM 路由和会话权限对应；Token 有效期、撤销、退出与 Host 重启行为须明确。CORS 不能替代鉴权。

### 7.2 展示合同

| 文件 | 首版行为 |
|---|---|
| 常见图片 | 消息中默认展开；点击图片在新标签页打开；保留下载 |
| SVG | 以安全图片方式内联；点击新标签页查看安全呈现；可下载原文件 |
| Markdown | 安全渲染、可阅读，始终保留下载源文件 |
| 代码/文本 | 只读预览和下载 |
| PDF | 浏览器预览或下载；不自行开发 PDF 编辑器 |
| 其他二进制 | 下载，不强行文本解码 |
| 超大文件 | 有界预览/明确提示，保留合法下载路径 |

- Agent 生成产物后，消息出现可点击文件卡；生成图片必须能直接在消息里看到，而不只是显示一个 VM 路径。
- 文件树是补充入口，不能成为用户寻找刚生成图片的唯一方式。
- 超链接默认新标签页，设置 `noopener` 等适当属性；只允许安全协议。
- Markdown 必须净化；SVG 不可注入主页面 DOM 或执行脚本。
- 新标签页查看 SVG 也不能把任意用户 SVG 作为主应用同源的主动文档执行：使用隔离/受限呈现；原始文件另走附件下载。
- 文件元数据和卡片持久化引用应能在重新打开历史后解析；文件已被删除时显示失效提示，而不是伪造可下载状态。
- 原始图片和 Markdown 下载与预览同时存在，不能用缩略图替代原文件。凭据文件不得作为自动展示产物。

产物发现需接入真实工具结果/Host 文件元数据；不得只依靠猜测助手文本中的路径。具体文件变更事件与刷新策略在实现中定义。

### 7.3 同源文件网关契约（新增，待实现）

- 浏览器使用统一入口下的同源文件 URL。每个请求均检查当前用户、固定 VM 路由及会话/workspace 归属；后端继续验证文件授权、实际路径和文件边界。
- 后端目标由服务器配置选择，浏览器不能提供任意 Host URL、目标 IP 或代理 URL；不得成为开放代理，不能借后端重定向逃离授权目标。
- Host 服务凭据与文件内部授权由服务器控制，不因代理改造暴露管理员凭据；浏览器缓存不保存授权 Token。
- 大文件请求／响应必须有界流式传输并处理背压。网关及外层反向代理不得把完整正文缓冲到内存或临时磁盘，不启用正文持久缓存；VM 可保留现有安全临时上传及原子发布机制。
- 保留已有大小／批次限制、取消、租约和完成事件语义。支持下载所需的状态码／Range／Content-Type／Content-Disposition，不能破坏 PDF、SVG 安全策略或附件下载。
- 新请求在退出、撤权或路由失效后拒绝；未完成上传不得在授权失效后发布成功。已完成下载无法撤回。进行中流的中止／完成应明确报告，失败后不自动重放上传。
- 网络中断、超时及后端失败必须结束并清理相应流资源，不能报假成功。具体路由和超时数值在实现契约中记录，不更换现有 TransferServer 协议来规避这些要求。
- 网关不记录文件正文、聊天正文、Cookie 或可重用下载授权；健康诊断仅含必要脱敏元数据。

### 7.4 浏览器缓存与原生历史（访谈已确认，待实现）

- Pi 原生 VM 历史是唯一权威来源；浏览器只缓存聊天正文和简短工具摘要，不建立第二套权威会话库。附件原件、完整工具输出及凭据／授权 Token 不缓存。
- 默认每账号全局 200 MiB 或 20000 条消息，任一达到即淘汰；可在简单设置中调整。流式片段不分别计为消息。不额外限制缓存对话数量。
- 仅 VM 确认接受用户消息才刷新 7 天近期激活计时；阅读、复制、编辑草稿、发送失败、后台输出和轮询不刷新。当前对话优先；近期激活的最多 5 个未归档对话各预取最新 100 条，不预取全部历史或附件。
- 超过 7 天可在启动／空闲时释放聊天缓存，当前阅读不被打断；容量压力下优先淘汰最久未访问对话，超大当前对话裁剪更早缓存。浏览器缺少可信激活记录时不猜测热度。
- 缓存先展示、后台增量核对；更早的 Pi 原生历史向上滚动按需加载，保留阅读位置并采用有界渲染。缓存预算不能成为 VM 历史可访问长度上限。
- 缓存按账号与明确 VM 环境标识隔离；退出保留磁盘缓存，重新验证网页身份后才展示。确认改绑 VM 环境后清除旧环境缓存；VM 明确删除历史后同步清除相关缓存，网络失败不是删除证据。
- 文字草稿独立保存，退出／刷新后保留；默认清聊天缓存不清草稿。消息确认接收后只清已发送版本，不覆盖期间新编辑内容。首次讨论的 20 MiB／1000 条和“不按日期释放”已由以上规则替代。
- 身份有效但 VM 离线时可只读缓存、编辑草稿；禁用发送、合并、归档和删除，不排队执行离线操作。重连同步后由用户明确发送。冷对话仍可跟踪必要任务状态，不因此同步全部正文或刷新激活计时。
- 不承诺网关离线时关闭页面后仍可重新启动网页，不据此新增 Service Worker/PWA 离线应用。未确认的滚动跟随细节、运行中发送默认方式继续保留为访谈未决项。

## 8. 连续性与错误语义

| 场景 | 首版承诺 |
|---|---|
| 关闭网页、短暂断网 | Pi 工作继续；恢复后可看到状态和结果 |
| Web 重启 | 不停止 VM 内 Host/Pi 工作 |
| 前后台切换、online、重连 | 主动与 Host 状态对齐，丢弃过期事件，避免重复呈现 |
| 后台任务完成 | 在允许的浏览器能力范围提供标题/角标/通知；权限拒绝时仍可看到完成状态 |
| Host/Pi/VM 重启 | 保留已落盘历史；未完成轮次明确标记中断；不自动重放副作用命令 |
| 认证失败、限流、超时、断流 | 分别给出可读错误和适当重试入口；不默默切换帐号，不自动重放未知结果操作 |

本版不要求 VM 重启后自动继续执行上一轮，不把“完成历史恢复”写成“执行恰好一次恢复”。
