# Cold legacy enrollment

This maintenance path imports Pi1.1.0 and Codex0.159.1 into newly allocated managed backing roots. It does not attach ownership markers to an old mutable directory. No service stop, migration, mount, block-device change or production-data access has been executed as part of implementation.

`withReadonlyLegacyExport` is the input boundary. The trusted legacy cut worker supplies its still-held physical publication lease, a live future-admission-retired/full-descendant-drained check, and the complete adapter-sealed source group. The worker verifies the current kernel mount table, canonical directory identity, a read-only ext4/XFS superblock and a read-only underlying block device (`/sys/dev/block/<major>:<minor>/ro`). Nested mounts are refused. A read-only bind of a writable device, a mode-0400 file, a marker, a hash, a receipt, or an arbitrary `ColdExport` object cannot qualify a source. An immutable snapshot export is distinct from the writable backup destination disk. The software reads these properties; it never creates snapshots, remounts disks or changes device flags.

The operator reviews explicit per-member old-root → new-root mappings. Every source belongs to the exact selected member; each operational path needs one unambiguous mapping. `relocateColdCheckpoint` verifies the original full group seal, copies into a new private staging directory, retains the original group/capture time/native IDs, and creates a new checkpoint ID and content seal. The original export is preserved. Registry cwd/task-root/project paths and Pi session-header cwd/parent-session paths are rewritten. User and tool transcript strings remain historical text.

For Codex, relocation requires the exact pinned SQL schemas and migrations. It rewrites selected `threads.cwd`, `threads.rollout_path`, selected `project_roots.path`, native/sqlite homes, and the native `session_meta`/`turn_context` cwd fields. Unknown schemas, unmapped paths and external `agent_path` resources fail closed. It does not perform arbitrary text replacement, activate old configuration, restore authentication or replay queued commands. Normal native adapters validate the relocated graph before publication.

`ColdEnrollmentCoordinator` stages a durable review containing the original/new manifest digests, mappings, every typed rewrite and the exact account-child plan digests. The production composition is `startColdEnrollmentControl` in `cold-enrollment-control.ts`. It temporarily registers the exact staged point with `ManagedSourceAuthority.withEnrollmentPoint`, calls scoped `BackupRepositoryClient.backup` with every member and the exact expected checkpoint ID, and checks the actual succeeded job, repository-read verdict and every member manifest digest. Source material crosses the existing SO_PEERCRED-authenticated checkpoint stream to the independent key service; the source worker never reads its key root. The maintenance caller then uses the normal pinned account/native recovery plans. Approval precedes publication. Per-account progress is durable; retry reconciles committed native/registry receipts and preserves completed tasks. A failed account leaves the parent partial. It does not claim an atomic transaction across accounts. A process crash during an individual native publication is covered by the source group's durable `ManagedPublicationGate` until the same approved child reconciles.

No browser accepts arbitrary export paths, root mappings, lease descriptors, archive callbacks or qualification claims. The private maintenance socket and CLI must be installed under the reviewed service principals. `src/cold-enrollment-cli.ts` accepts only a private client file, action, operation ID, revision and reviewed digest; it cannot supply filesystem paths, root mappings, actor identities or qualification flags. The fixed source-owned profile supplies those choices. The old Host exposes `hold-cold-export` only when its private cut root and writer fence are configured. It retains the actual kernel EX and full logical group lease while each heartbeat rechecks admission retirement and descendant custody; connection/proof loss revokes the source capability. The ordinary live backup scheduler continues to consume current sealed checkpoints and does not call enrollment.

## Evidence and installation gates

Synthetic tests exercise real Pi SessionManager history, typed relocation, actual pinned Restic archive/read verification and the actual recovery publication journal. Codex tests exercise the pinned schema, typed SQL/rollout relocation and actual native SQL publication into new synthetic roots. Ordinary mutable directories and fabricated export objects are refused. Managed-source restart tests retain known inode identities, reject replacement/unknown roots and preserve pending native-publication admission fences.

**UNVERIFIABLE in the current unprivileged test environment:** a real read-only block-backed snapshot, the legacy service's multi-UID exclusive cold export, independently installed maintenance/source/key worker identities and the source-UID-readable read-only export view, and production migration. A sealed-memory fixture or a same-UID synthetic test is not evidence for those gates. They require separately authorized installation and an end-to-end rehearsal before an existing production root is enrolled. The code must continue to refuse enrollment when the actual OS prerequisites are absent.

## Explicit installation and calls

Enable the old Host control with its existing `writerFence` and an existing private `coldCutRoot`; the old Host UID owns that authority. Enable `startColdEnrollmentControl({socket, profile, accounts, authority, broker})` in the qualified source Host after its checkpoint export server starts. Its socket is under the unmounted source `authority/` directory. The configured source UID is the only accepted maintenance peer. The maintenance profile must be owned by that UID and mode0600; examples are in `deploy/source-managed/cold-enrollment.example.json` and `cold-enrollment-client.example.json`. Do not expose this socket through HTTP.

The source UID reads only the mounted immutable sealed export, its own staging/operation records, and IPC-only broker configuration. The legacy UID retains its retirement/exclusive cut and never gets the new backing roots or repository key. The key UID receives only the authenticated checkpoint stream and returns independently verified repository metadata. A source-UID-readable private read-only export view must be installed explicitly, for example a reviewed idmapped read-only view of the frozen export. Do not chown or attach ownership markers to a mutable legacy root. The export must already be a complete adapter-sealed group captured from the verified cold snapshot; this command does not create a filesystem snapshot.

Run the built CLI as the dedicated source UID (identity setup is an operator step):

```sh
node dist/src/cold-enrollment-cli.js plan --client /private/cold-client.json
node dist/src/cold-enrollment-cli.js status --client /private/cold-client.json --id <operation-id>
node dist/src/cold-enrollment-cli.js approve --client /private/cold-client.json --id <operation-id> --revision 1 --digest <reviewed-digest>
node dist/src/cold-enrollment-cli.js publish --client /private/cold-client.json --id <operation-id> --revision 1 --digest <reviewed-digest>
```

The first call only stages and archives material and prepares account plans. Review its mappings, typed rewrite inventory and per-account plans before approval. Publishing is the explicit irreversible maintenance step. If it fails after a child committed, repeat the same approved publish identity; do not change the plan, delete its journals, recreate target directories, or run an unrelated recovery to clear the admission gate.
